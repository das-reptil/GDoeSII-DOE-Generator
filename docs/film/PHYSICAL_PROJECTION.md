# Physical projection GS mode

The GS film/batch generator provides a **Physical projection** propagation mode for targets whose physical scale is much larger than the DOE itself.

This mode is intended for geometries such as the current rotating-film concept:

```text
DOE raster:          4096 x 4096 px
DOE pixel pitch:     500 nm
Wavelength:          532 nm
Target distance:     300 mm
Desired front width: 50 mm
```

## Why same sampling is not sufficient

The historical GS implementation uses the same lateral sampling pitch in the DOE and target planes. A `500 nm` DOE pitch would therefore make a 4096-pixel target field only about `2.048 mm` wide, which cannot represent a 50 mm projected image.

Physical projection uses the single-FFT Fresnel scaling relation instead.

## Target-plane sampling

For source-plane pitch `dx1`, wavelength `lambda`, distance `z` and `N` samples, the destination-plane pitch is

```text
dx2 = lambda * z / (N * dx1)
```

The same expression is applied independently in X and Y.

For the reference film geometry:

```text
lambda = 532 nm
z      = 300 mm
N      = 4096
dx1    = 500 nm
```

this gives

```text
dx2 = 77.9296875 um/px
```

and therefore

```text
target field width = 4096 * 77.9296875 um
                   = 319.2 mm
```

A 50 mm target width occupies approximately

```text
50 mm / 0.0779296875 mm = 641.6 samples
```

which is consistent with the target scale required by the film concept.

## Numerical propagation

The implementation uses the single-FFT Fresnel form

```text
U2 = Q2 * FFT(Q1 * U1)
```

with quadratic Fresnel phase factors `Q1` and `Q2` in the source and destination planes.

For GS iterations the inverse is implemented as the exact reciprocal discrete transform

```text
U1 = conj(Q1) * IFFT(conj(Q2) * U2)
```

using orthonormal FFT normalization. This makes the numerical forward/backward pair reciprocal apart from normal floating-point error and avoids introducing an arbitrary gain into the GS loop.

The usual overall Fresnel propagation phase/amplitude prefactor is omitted because it is global and does not affect the phase-only GS solution or normalized intensity preview.

## Target width and generated film frames

The film GUI specifies target width in **millimetres**.

For an ordinary input frame this width refers to the complete source-frame width.

For frames generated by the built-in 360-degree yaw generator, `frames.json` records the front-facing source-image width. Physical projection uses that value as the reference automatically. This is important for the current animation, because the generated 1024-pixel frame intentionally contains a dark margin around a roughly 600-pixel front-facing image.

Example:

```text
frame canvas:             1024 px
front-facing reference:    600 px
requested target width:     50 mm
```

The complete 1024-pixel target-frame canvas is then represented by about

```text
50 mm * 1024 / 600 = 85.33 mm
```

while the front-facing logo itself remains about 50 mm wide. As the source image turns edge-on, its projected width becomes smaller naturally; it is not rescaled back to 50 mm on every frame.

## Same-sampling compatibility mode

The film GUI retains `Same sampling` as a compatibility and diagnostic mode. In that mode the target width entered in millimetres is converted internally to the legacy micrometre parameter.

## Off-axis target position

For a parallel physical target plane, X/Y target displacement continues to be represented by the exported steering phase ramp. GS synthesis and brightness statistics are evaluated in centered local target coordinates.

## Pan / tilt

The first physical-projection implementation supports a **parallel target plane only**:

```text
pan  = 0 deg
tilt = 0 deg
```

The existing tilted-plane GS implementation remains available in `Same sampling` mode. Combining arbitrary target-plane tilt with the scaled physical-projection sampling requires a separate scaled tilted-plane propagator and is deliberately rejected rather than approximated silently.

## Sampling diagnostics

The implementation reports:

- DOE physical dimensions,
- physical target pixel pitch in X/Y,
- physical target-field dimensions,
- approximate number of target samples across the requested width,
- source Fresnel-chirp sampling warnings where applicable.

The derived values are written to the per-frame JSON metadata and to `summary.json`.
