# GS film / batch generator

The film workflow is intentionally restricted to **Arbitrary Image / Gerchberg-Saxton (GS)** DOEs.

Analytical generators such as Lens, Grating, Fresnel Zone Plate and Vortex remain in the normal single-DOE application and are not exposed in the film GUI.

## Separation of applications

The repository builds two Windows applications:

- `GDoeSII_DOE_Generator.exe` – general single-DOE generator.
- `GDoeSII_Film_GS_Batch.exe` – simplified GS-only film/batch generator.

The film implementation is kept under `src/film/`, its packaging configuration under `config/film/`, and film documentation under `docs/film/`.

## Input modes

The film application supports two target-frame inputs:

1. **Use existing frame directory** – process already prepared target images in sorted filename order.
2. **Generate 360-degree yaw frames from source image** – create an evenly sampled vertical-axis rotation and then process those generated frames.

For generated frames the default intensity mapping `black/red bright, white dark` is intended for the current POF logo workflow.

## GS propagation modes

### Physical projection

This is the default film mode. Source and target planes use physically different sample pitches according to the single-FFT Fresnel relation

```text
dx_target = lambda * z / (N * dx_DOE)
```

For the reference geometry

```text
4096 x 4096 px
500 nm DOE pitch
532 nm wavelength
300 mm target distance
```

the target sampling is approximately

```text
77.9297 um/px
```

and the complete target field is approximately

```text
319.2 x 319.2 mm
```

A 50 mm front-facing target therefore occupies about 642 target samples.

For frames generated by the built-in yaw generator, the recorded front-facing image width is used as the physical-width reference. The dark frame margin is preserved rather than incorrectly shrinking the actual logo to the requested width.

### Same sampling

The historical same-sampling GS path remains available for compatibility and diagnostics. It is also currently the mode used when a tilted GS target plane is required.

See [`PHYSICAL_PROJECTION.md`](PHYSICAL_PROJECTION.md) for the numerical model and limitations.

## Film batch workflow

The film application performs:

1. optional target-frame generation,
2. source-frame brightness analysis,
3. independent GS calculation for every frame,
4. target-plane simulation for every generated DOE,
5. reconstructed-power / brightness analysis,
6. per-frame brightness-compensation recommendations,
7. 16-bit DOE + JSON metadata export,
8. simulation PNG export,
9. ring-layout CSV generation.

Each frame is an independent GS problem. No analytical DOE type is mixed into the film workflow.

## Output structure

A batch output directory contains:

```text
film_config.json
summary.json

frames_raw/                 # only when generated by the film GUI
  frame_000.png
  ...
  frames.json

doe/
  DOE_000.png
  DOE_000.json
  DOE_001.png
  ...

simulation/
  sim_000.png
  sim_001.png
  ...

statistics/
  frame_source_statistics.csv
  brightness_statistics.csv

layout/
  DOE_ring_layout.csv
```

`summary.json` and the per-frame metadata record the selected propagation mode and, for physical projection, the derived target-plane pixel pitch and field dimensions.

## Physical-projection pan / tilt limitation

Physical projection currently requires a parallel target plane (`pan = 0`, `tilt = 0`). The general tilted-plane GS implementation is retained in `Same sampling` mode. A combination of arbitrary plane tilt and scaled target sampling is not silently approximated.
