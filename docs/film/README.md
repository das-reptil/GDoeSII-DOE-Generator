# GS film / batch generator

The film workflow is intentionally restricted to **Arbitrary Image / Gerchberg-Saxton (GS)** DOEs.

Analytical generators such as Lens, Grating, Fresnel Zone Plate and Vortex remain in the normal single-DOE application and are not exposed in the film GUI.

## Separation of applications

The repository now builds two Windows applications:

- `GDoeSII_DOE_Generator.exe` – general single-DOE generator.
- `GDoeSII_Film_GS_Batch.exe` – simplified GS-only film/batch generator.

The film implementation is kept under `src/film/`, its packaging configuration under `config/film/`, and film documentation under `docs/film/`. Frame analysis, optional frame generation, brightness handling, batch processing and ring-layout generation therefore do not clutter the general DOE GUI.

## Input modes

The film application supports two target-frame inputs:

1. **Use existing frame directory** – process already prepared target images in sorted filename order.
2. **Generate 360-degree yaw frames from source image** – create an evenly sampled vertical-axis rotation and then process those generated frames.

For generated frames the default intensity mapping `black/red bright, white dark` is intended for the current POF logo workflow. It keeps black and saturated red source features bright in the monochromatic target while suppressing white/light background areas. Other mappings are available for already prepared grayscale targets.

## Film batch workflow

The film application performs:

1. optional target-frame generation,
2. source-frame brightness analysis,
3. independent GS calculation for every frame,
4. target-plane simulation for every generated DOE,
5. reconstructed-power / brightness analysis,
6. per-frame brightness-compensation recommendations,
7. 16-bit DOE + JSON metadata export,
8. simulation PNG export,
9. ring-layout CSV generation.

Each frame is an independent GS problem. No analytical DOE type is mixed into the film workflow.

## Output structure

A batch output directory contains:

```text
film_config.json
summary.json

frames_raw/                 # only when generated by the film GUI
  frame_000.png
  ...
  frames.json

doe/
  DOE_000.png
  DOE_000.json
  DOE_001.png
  ...

simulation/
  sim_000.png
  sim_001.png
  ...

statistics/
  frame_source_statistics.csv
  brightness_statistics.csv

layout/
  DOE_ring_layout.csv
```

## Current optical scaling limitation

The film batch currently uses the same target sampling model as the existing GS implementation. `GS target width (um; 0=fit)` therefore refers to the current same-sampling calculation plane.

This is **not yet the physical-projection mode** required to directly represent, for example, a 50 mm projected target at 300 mm distance from a 4096 x 4096 DOE with 500 nm DOE pitch.

A scaled/physical Fresnel propagation mode remains a separate numerical extension. The film GUI states this explicitly so a user does not accidentally enter `50000 um` into the current same-sampling target-width field and assume it represents the intended projection geometry.
